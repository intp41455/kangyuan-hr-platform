## 一、首次部署（Vercel CLI 方式）

| Vercel CLI | 已通过 `npm i -g vercel` 安装 |
| Node.js | ≥ 16 |
| 项目目录 | `webui/` |

### 步骤 2：首次部署

```bash

```

回答首次部署的几个问题（按回车接受默认即可）：

| 问题 | 推荐回答 |
|---|---|
| `Set up and deploy?` | `Y` |

| `Link to existing project?` | `N` |
| `What's your project's name?` | `kangyuan-hr`（或自定义） |

| `Want to modify settings?` | `N`（已通过 vercel.json 配置好） |

部署成功后终端输出：

```

```

**这就是公网访问地址，任何人打开即可访问，自动 HTTPS、全球 CDN 加速。**

1. 浏览器打开输出的 Production URL

## 二、后续更新部署

每次修改代码后，执行两步即可重新部署：

```bash
# 在 webui/ 目录下
npm run build      # 重新构建静态文件到 dist/
vercel --prod      # 一键部署到生产环境（约 10 秒）
```

Vercel 会自动：
- 上传新的 dist/ 文件
- 刷新 CDN 缓存
- 保留旧版本快照（可在 Vercel 控制台一键回滚）

---

## 三、配置文件说明

部署相关配置文件已在项目根目录就绪：

### vercel.json
- `framework: vite` — 告诉 Vercel 用 Vite 构建
- `buildCommand: npm run build` — 构建命令
- `outputDirectory: dist` — 构建产物目录
- `rewrites` — SPA 路由配置，确保 `/self/payslip` 这种深层路径刷新不 404
- `headers` — 静态资源长缓存（一年），加速访问

### netlify.toml（备选）
- 如果改用 Netlify 部署时使用，规则与 vercel.json 等价

## 四、自定义域名（可选）

默认域名是 `xxx.vercel.app`，如需绑定企业自有域名：

1. 在 Vercel 控制台进入项目 → Settings → Domains
2. 输入你的域名（如 `hr.kangyuan.com`）
3. 按提示到域名注册商添加 CNAME 记录指向 `cname.vercel-dns.com`
4. 等 DNS 生效（通常 5-30 分钟），Vercel 自动签发 SSL 证书

## 六、常见问题

| 问题 | 答案 |
|---|---|
| 部署后白屏？ | 检查 vercel.json 是否包含 rewrites 规则（已配置好） |
| 深层路径刷新 404？ | rewrites 规则未生效，确认 vercel.json 在项目根目录 |
| 国内访问慢？ | Vercel CDN 在国内有节点，但仍建议加自有域名走 Cloudflare CDN |
| 怎么回滚？ | Vercel 控制台 → Deployments → 选历史版本 → Promote to Production |
| 怎么删除部署？ | Vercel 控制台 → Project → Settings → Advanced → Delete Project |
| 改了 mock 数据怎么生效？ | 改 `webui/src/mock/data.js` → `npm run build` → `vercel --prod` |
| 后续对接真实后端 API？ | 把 `src/mock/data.js` 的 import 替换为 fetch/axios 调用即可 |

## 七、备选部署平台

如 Vercel 不便，可改用以下任一平台（dist/ 文件夹通用）：

| 平台 | 拖拽部署地址 | 特点 |
|---|---|---|
| Netlify | https://app.netlify.com/drop | 国内访问稍快 |
| Cloudflare Pages | https://pages.cloudflare.com | 全球 CDN 最快 |
| GitHub Pages | 需 push 到 GitHub 仓库 | 完全免费但需配 404.html |

`netlify.toml` 配置已就绪，可直接用 Netlify。
