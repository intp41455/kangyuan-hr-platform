## 一、编码规则

### 1.1 员工编码 (Employee ID)

- **格式**: `E` + 6位十进制自增序号
- **示例**: E000001、E000002、E000003 ...
- **起点**: 从 E000001 开始，按生成顺序自增
- **适用**: 员工花名册唯一标识，全局唯一且不可修改

### 1.2 部门编码 (Department ID)

- **格式**: `D` + 层级码(每级2位十进制自增序号)
- **一级部门**: D + 2位序号，如 D01、D02、D03 ...
- **二级部门**: 父编码 + 2位子序号，如 D0101、D0102 ...
- **三级部门**: 父编码 + 2位子序号，如 D010101、D010102 ...
- **示例**:
  - 一级: D01 (教育事业部)
  - 二级: D0101 (教学部 → 教育事业部下属)
  - 三级: D010101 (语文教研组 → 教学部下属)
- **规则**: 每新增一层子部门追加2位，支持最多N级扩展

### 1.3 岗位编码 (Position ID)

- **格式**: `P` + 4位十进制自增序号
- **示例**: P0001、P0002、P0003 ...
- **起点**: 从 P0001 开始，按生成顺序自增
- **适用**: 岗位体系唯一标识，跨部门复用同一岗位编码

## 二、枚举字典

### 2.1 员工状态 (EMPLOYEE_STATUS)

| 代码值 | 中文名称 | 说明 |
|--------|----------|------|
| PENDING_ONBOARD | 入职待报到 | 已发放offer并确认入职，尚未正式到岗报到的新员工 |
| PROBATION | 试用期 | 已入职报到，处于试用期考察阶段的员工 |
| REGULAR | 正式 | 通过试用期转正，签订正式劳动合同的员工 |
| TRANSFERRING | 调动中 | 正在办理跨部门/跨地区岗位调动手续的员工 |
| PROMOTING | 晋升中 | 正在办理职级或岗位晋升审批流程的员工 |
| PENDING_LEAVE | 待离职 | 已提交离职申请，处于离职交接期的员工 |
| LEFT | 离职 | 已完成离职手续，正式离开公司的员工 |
| RETIRED | 退休 | 达到法定退休年龄，办理退休手续的员工 |

## 三、API 方法速查

| 方法 | 说明 |
|------|------|
| `genEmployeeId()` | 生成下一个员工编码 E000001 ~ |
| `genDeptId(parentDeptId?)` | 生成部门编码，无子参生成一级部门，传入父编码生成子部门 |
| `genPositionId()` | 生成下一个岗位编码 P0001 ~ |
| `listAllEnums()` | 返回全部5套枚举的完整清单(代码/名称/说明) |
| `validateEnum(type, value)` | 校验 value 是否为 type 枚举的合法代码值 |
| `genIdInfo(value)` | 反解编码字符串，返回类型/层级/序号/父编码等信息 |
| `generateDictionaryMarkdown()` | 生成本字典 Markdown 文档字符串 |
